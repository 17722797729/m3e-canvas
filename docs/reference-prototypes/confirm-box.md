# 确认框（已重做）—— 交接说明

`confirm-box-component.json` 是作者在「上传屏幕2」里**手摆的那一版原稿**：一个 `box`（320×200、
圆角 28、`surfaceContainerHigh`）+ 标题 + 一条正文带（里面是正文）+ 两颗按钮。

目标：把它**融成一个部件**，命名「确认框」，放在 **组件 → 容器**（挨着「对话框」，`KIND_ORDER` 里
紧跟 `dialog`）。上一版做到一半的那个 `confirmBox` **已经整体删掉了**（连 `Item.label3`、面板那几节、
提示词与测试一起），所以这里是干净的一遍；作者画布上那一枚也会在下次读入时被丢掉（见 `REMOVED_KINDS`，
重做时记得把它从那张表里拿出来）。

## 从原稿量出来的数（作者的稿子在哪一项都别改）

| 原稿 | 融合进部件 |
|---|---|
| `box` 320×200、圆角 28、`surfaceContainerHigh` | 同左（宽高可改，高跟着内容走） |
| `text`「温馨提示」20dp @ (114, 14) | 20dp、**居中**、y=14 |
| 正文带 260×72 @ (26, 48)，正文「确认当前操作？」18dp @ **带内** (19, 10) | 带高 **72**、y=48；正文 18dp、**左对齐**（带内左 25、上 10）；正文折行时带（和框）跟着长，不裁字 |
| `button` ×2 各 104×49 @ y=130（左 20 / 右 27，手摆差 7dp） | 104×49、y=130，**左右各 20**（对称），中间那道缝 72 |
| 下留白 21 | 21 ⇒ 总高 14+24+10+72+10+49+21 = **200**；没标题 166、没正文 118 |

字段：`label` 标题、`supporting` 正文、`label2` 确认按钮的字、`label3` 取消按钮的字（上次为它加过
`Item.label3` 与存档字段表里的一项，重做时照旧加回去）。

## 作者对行为的要求（原话，逐条都是硬要求）

- 「**不管是确认还是取消，默认关闭此面板。**」—— 先做过一版，随后改成「**改回默认无操作**」；作者后来
  又自己把这段逻辑加了回来，并要它成为组件本身（「里面我加了隐藏面板的逻辑……覆盖当前的确认框」）。所以
  **新落下的确认框两颗都配着「点一下 → 隐藏这一块」**（`CONFIRM_BOX_HIDE_STEP` / `makeItem`）：预览里点
  确认或取消都会把这一块收起来。去处仍旧归作者 —— 「行为」一节里可以把它改成「关闭当前面板」
  （`CLOSE_PANEL_TARGET`）、跳去某一屏，或者清掉。
- 「**取消和确认是完全一样的普通按钮，跟名称没有关系。**」→ 两颗的机制必须一模一样：点下去都是
  「那颗按钮自己的状态机 → 那颗按钮自己的动作」，各自独立配置，谁也不比谁特殊。
- 「**取消按钮就是个普通按钮就行。**」→ 没有配去处时它就是一颗不动的按钮；但它**自己那一下不被别人
  拿走**（见下一条）。
- 「点击相当于是点击整个容器」是作者**报的问题**：整块部件不吃点击，**只有里面那两颗按钮吃**。
- 「置灰并响应时，是针对按钮，而不是整个组件。」→ 状态里的「置灰并停止响应」灰的是**那两颗按钮**，
  不是整块框（`disablesWholePart` 的那条判定）。

## 两个已经踩过的坑（这次务必避开）

1. **槽位入口不能只看 `actions`。** 作者常常**只配状态机**（`slotFlows.cancel`，「点击后变化 → 隐藏」）。
   预览里那个槽位入口的条件应该是：
   `it.actions || it.slotFlows || 融合部件`（见 `components/Preview.tsx` 里 `slotTaps` 那一处）——
   以前只看 `actions`，于是那颗按钮根本没人接，点了没反应。
2. **槽位机器的 look latch 在 `<部件id>:<槽位>`，而部件自己的外观只解 `<部件id>`。** 机器跑了、屏幕却
   什么都没变（作者配「取消 → 隐藏面板」不生效就是这么来的）。融合部件必须把槽位那几台机器的状态并进
   自己：`resolveSlotStates` + `mergeSlotStates`（`lib/tokens.ts`）。栏的每一格**不要**并：那是一个落点，
   它的 hidden/disabled 说的是那一格（见 `Preview` 的 `tabLook`）。
3. **「改变属性 → 隐藏」那一步的"归属"不能是空的。** 它不是状态机里那个 `hidden`，而是一份**点住了的
   外观补丁**，落点算的是 `a.target ?? owner`（见 `Preview` 的 `runRuleAction`）。主按钮那一下本来就带着
   这一部件自己，而槽位那一下以前传的是 `null` —— 于是"机器跑了、屏幕什么都没变"（作者报的「确认生效、
   取消失效」就是这个）。融合部件里那颗按钮**不是画布上独立的部件**，它的"自己"就是这一块，所以槽位那一
   步的归属必须是**这一部件自己**：`slotLookOwner`（`lib/tokens.ts`），`pickSlot` 与定时那一条循环都用
   它。栏的每一格不在此列（`slotLookOwner` 给的是 `null`：那一格自己的补丁不该盖到整条栏上）。
4. **`slotFlows` 不能用读 `slotStates` 的那支笔读。** 一个键底下是**一台机器**（一个 flow 对象），不是
   一串。曾经套上 `[flow]` 去读，于是存下来的 `{"cancel": {…}}` 读回来成了 `{"cancel": [{…}]}`：
   `firstTapStep` 找不到 `.steps`，那一格配的东西整个失效，`hasTimedSteps` 还会直接抛（读到这种文档预览
   就挂）。现在有专门的 `readSlotFlows`（`lib/project.ts`），两种形状都认。

## 还有两条画法上的规矩（上次都做了，重做时照旧）

- 两颗按钮的**按下手感一样**（预览里 pointer 光标 + 按下缩到 0.94），**不看**它有没有配去处；
  编辑器画布里两颗都不挂事件（那里按住按钮是"把这一块拖走"的手势，见 `swallowsInnerTap`）。
- 预览里一颗按钮**永远吞掉自己那一下**，绝不让它冒到外面那层容器上（`swallowsInnerTap` 的第二半）。
